# Express the SQL Server Destination as Inline Fields with an Env Credential Reference

The `sqlserver` destination — the repo's first network destination — is expressed as inline discrete fields under `destination`, never as a connection string (the form the glossary's Connection Reference entry explicitly avoids): `host` (required, non-empty), `port` (optional, default `1433`), `database` (required, non-empty; the database must already exist — creating one is DBA work, not load work), `schema` (optional, default `dbo`), `user` (required, non-empty), `password_env` (required, non-empty), `encryption` (optional, `required` by default, or `optional`), and `trust_server_certificate` (optional, default `false`). Authentication is SQL auth only: Integrated auth on Unix drags in GSSAPI system libraries against the single-file promise, and AAD tokens are Azure-specific, so both stay out of this slice. `password_env` names the environment variable holding the password — a credential reference in the glossary's sense, never a credential value — so the definition stays committable and shareable (ADR-0011). The top-level `dataset` keeps naming the table exactly as it does for `duckdb` — required and non-empty — and must not contain a dot: qualification is physical addressing and lives in `schema`, so a dotted name fails `invalid_dataset_name` with a message pointing there. `path` is not a `sqlserver` key; writing one fails as an unknown key under ADR-0037. The load-definition contract stays `version: 1` — everything here is additive and existing definitions parse unchanged — and the report's `destination_summary` keeps echoing the block as written, safe by construction because no key of the contract can carry a secret (ADR-0061). Two behaviors ship fixed instead of as knobs: a hardcoded 15-second connect timeout (the released Tiberius has no timeout configuration, and a hang must become a clean failure), and `application_name` pinned to `data-spark` so DBAs can identify the tool's sessions server-side.

Validation of the block stays in the Definition phase and stays offline — it never opens a network connection, so connectivity, authentication, and TLS failures remain write-phase facts (their transient-vs-terminal classification is a separate decision). Three codes join the Definition-phase vocabulary: `invalid_destination_config` for a block that is incomplete or contradictory for its connector — a missing or empty required key, a dotted `schema` — following the `invalid_schema_config`/`invalid_transform_config` naming pattern; `unresolved_credential_reference` when the environment variable `password_env` names is unset or empty at load time; and `invalid_dataset_name` for the dotted-dataset case. The `encryption` knob exists because of a measured risk, not symmetry: `required` is the secure default and the CI path (the spike proved the rustls handshake against a self-signed v1 container certificate with `trust_server_certificate: true`), but the tool's real production posture today is SSMS `Encrypt=Optional`, and a server that declines a required encryption level makes the released Tiberius panic (prisma/tiberius#425) — without the knob, a production server with encryption disabled would leave the tool unusable there until a new release. `optional` maps to Tiberius `EncryptionLevel::Off` — login encrypted where possible, data traffic per server policy — reproducing the proven SSMS posture. No third, fully-unencrypted state ships: it would send login credentials effectively in the clear.

This decision reaffirms ADR-0011 (definitions carry references, never credential values) and narrows ADR-0012 for v0.5.0: of that ADR's three resolution sources, only environment-variable references ship now — connection profiles and secure prompts are deferred, and ADR-0013's `connections.yaml` location stays accepted but dormant until profiles arrive. Alternatives rejected: a connection-string key (opaque, secret-prone, and on the glossary's Avoid list); profile-first indirection now (`connection: <name>` resolving through `connections.yaml` would add a second file contract — parsing, resolution order, failure vocabulary, docs — ahead of the first network destination proving the seam, against the cycle's single-session slicing rule); `${VAR}` interpolation inside values (it would graft expansion semantics onto the whole strict-literal contract of ADR-0037 for no gain over one explicit reference key); named-instance support (Tiberius needs the `sql-browser` feature and UDP 1434 discovery — a static port covers the need today, and the key set stays additive if instances ever matter); timeout knobs (a guessed need — the hardcoded connect timeout keeps hangs failing cleanly, and knobs can arrive additively when a real environment demands them).
