# Classify Transience at the Originator and Retry Only Provably Uncommitted Units

The retry engine (ADR-0022) lands as an orchestrator-owned loop in the write phase, and it retries only failures classified **transient by their originator** — the connector that raised them. The classification lives on the destination write-failure type, the existing carrier of destination-owned facts (ADR-0021): every existing constructor and `From` lifting defaults it to terminal, and only an explicit `Transience::Transient` at the raising site makes a failure retryable. The classification obligation makes ADR-0022's boundary rule a hard condition: a failure may be classified transient only when the failed attempt provably committed nothing new to the destination **and** the session can accept a re-attempt of the same unit — any uncertainty means terminal, mandatorily. The shared `LoadFailure` type is untouched: source, schema, and definition failures cannot be classified and are never engine-visible.

The **retry unit** is the failed port operation re-invoked with identical input: `begin(mode)` re-called, or `write_chunk` re-called with the same chunk. Deterministic chunks (ADR-0045) make "the same unit" well-defined, and the batch is already materialized when the write fails. The terminal `commit` is **never engine-retried, enforced structurally**: committing consumes the writer, so after a failed commit nothing remains to re-call; future polling-style commit verification (BigQuery job polling) is connector-internal retry, not engine re-invocation. Source-side operations are not engine-wrapped: local source failures are never transient, a mid-stream chunk pull is not a re-runnable unit, and future paged sources will retry internally against their own units. On a transient failure with remaining budget the engine waits through an injectable sleeper and re-attempts; on a terminal failure or an exhausted budget it surfaces the **last failure unchanged** — same code and message, no wrapper code — while failed attempts of retried units accumulate in an orchestrator-held attempt log consumed by report assembly (ADR-0050). The port contracts do not change.

**No shipped connector classifies any failure transient**, so the engine is provably idle in the current all-local matrix — statically verifiable, since no transient construction exists outside the test connectors. Worked through the four writer cells: `begin` failures, Parquet staged-part write failures, and DuckDB append `INSERT` errors are re-attempt-safe in principle; Parquet append rename failures (the part may already be visible) and DuckDB full-refresh in-transaction statement errors (the transaction aborted, the session is dead) are terminal always. All remain terminal in this slice regardless, and the first classification is deferred to the first connector whose failures are genuinely transient.

Alternatives rejected: classifying any current local error transient (a local disk that fails once fails again, and a wrong transient marking risks duplicate writes — the one harm the safety model exists to prevent); orchestrator-inferred transience from failure codes (the orchestrator cannot know what a connector committed, and inference re-creates the uncertainty the originator rule eliminates); a `retry_exhausted` wrapper code (report readers would branch on a new code that states less than the attempts array already does); idempotency-key machinery now (the safety model makes retry-caused duplicate writes structurally impossible, and per-connector keys belong to the connectors that need them).
