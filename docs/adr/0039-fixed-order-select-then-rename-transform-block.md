# Fixed-Order Select-Then-Rename Transform Block

Data Spark will express field selection and rename mapping as one optional top-level `transform:` block with two fixed keys — `select`, a list of source field names, and `rename`, a map of source field name to dataset field name — rather than as an ordered list of user-sequenced transform steps. The evaluation order is fixed by the contract: selection evaluates first, against observed source names, with the select list order defining the dataset field order; the rename mapping evaluates second, applied simultaneously over the selected (or, without `select`, full observed) field set, so swaps like `{A: B, B: A}` are legal, unmapped fields pass through under their source names, and rename keys always mean source names. A fixed order keeps every definition readable without simulating a pipeline in one's head, and a fixed-key block stays inside the recursive strict contract (ADR-0037) instead of inventing a step grammar for two operations. The block fails strictly rather than degrading to no-ops: a block that transforms nothing, an empty select or rename listing, duplicate select entries, a rename key outside a declared select list (no implicit selection), identity renames, duplicate or empty rename targets, duplicate rename keys, and — with `select`, where the dataset shape is fully config-determined — a rename target colliding with another selected field's dataset name are all definition errors raised before any I/O; a select entry or rename key naming no observed field fails the load at read time, and a rename target colliding with a pass-through field name, reachable only without `select`, fails it there rather than silently dropping or merging a column. Rejected records keep their identity across the transform: the artifact names the dataset field alongside the source field a rename changed, while the recovered record content stays the original source shape.
