# Land Merge Loads on DuckDB Only and Decline Elsewhere

`load_mode: merge` — the keyed upsert ADR-0008 committed v1 to — ships on the `duckdb` destination only, and every other destination declines it through its declared mode support rather than through a parse error. Merge is a pure upsert: destination records whose merge key tuple matches a source record are replaced whole, unmatched source records insert, and records absent from the source stay — no delete semantics. The keys are always user-declared in a strict top-level `merge` block (`keys: [field, ...]`, ADR-0037), because the only shipped source is `local_file`, for which ADR-0009 mandates fail-fast key discovery; the block is cross-validated against the load mode before any I/O — `load_mode: merge` without the block fails `missing_merge_keys`, the block outside a merge load, an empty `keys` list, or a duplicated key name fails `invalid_merge_config`. Keys name dataset fields (after flatten, selection, and rename); a key naming no resolved dataset field fails `unknown_merge_key_field` at read time, side-effect-free, and a record holding null in any key field is a rejected record (`null_merge_key`) under the ordinary `reject_threshold`, because a null never equals anything under key equality.

Landing the mode per destination makes `Destination::supported_load_modes` load-bearing for the first time and forces the failure vocabulary to split: `unsupported_load_mode` now means exactly "this mode string is unknown", while a known mode a destination declines fails `unsupported_load_mode_for_destination`, with a message naming the destination and the modes it does support (`parquet destination does not support load mode: merge (supported load modes: full_refresh, append)`). One code for both cases would leave an operator unable to tell a typo from a capability gap, and would misname the fix — correcting a string versus switching destinations or modes. Parquet declines because a directory of immutable part files has no record identity to update; emulating merge by rewriting the whole dataset would be a full refresh wearing merge's name, with write amplification the mode's contract promises to avoid.

Alternatives rejected: emulating merge on Parquet via rewrite (semantically a full refresh, and the mode's meaning must not vary by destination); keeping one `unsupported_load_mode` code for both the unknown-string and declined-mode cases (conflates definition typos with capability boundaries); silently falling back to `full_refresh` where merge is unsupported (a silent semantics change destroying records the user asked to keep); inferring merge keys from destination constraints (key discovery is deferred with the database-table source, ADR-0009, and destination-side constraints do not exist on bootstrapped tables).
