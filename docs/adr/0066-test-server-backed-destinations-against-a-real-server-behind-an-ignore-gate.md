# Test Server-Backed Destinations Against a Real Server Behind an Ignore Gate

SQL Server is the first destination that needs a running server, and this strategy is written for every server-backed destination after it: integration tests run against a real server, never a mocked TDS layer, and the gate around them is precise. Only tests that open a live connection carry `#[ignore = "needs SQL Server"]`; T-SQL generation, type mapping, configuration parsing, and error classification stay ungated unit tests that run on any machine. A contributor without a server sees plain `cargo test` pass with a visible `ignored` count — never a runtime environment check that returns early and reports green while testing nothing. CI and the release workflow enforce the full suite with `cargo test --locked -- --include-ignored`, and the repo reserves `#[ignore]` for needs-a-live-server tests so that flag's scope stays exactly the server-backed suite. The server is exogenous to the test process: tests connect with fixed defaults that match the documented container one-liner (`localhost:1433`, `sa`, the documented test password), overridable through the `DATA_SPARK_TEST_MSSQL_*` environment family for anyone pointing at their own server, and never start containers themselves.

CI keeps the single `rust` job — the merge gate's required checks stay untouched — and wires the server in-job: a `docker run` of `mcr.microsoft.com/mssql/server:2022-latest` right after checkout, and an `/opt/mssql-tools18/bin/sqlcmd -C … "SELECT 1"` readiness loop immediately before the test step, so the measured 14 s pull + 5 s startup and ~2 GB of disk (spike run 31091458338, public runner) hide behind toolchain install, cache restore, and clippy — on warm runs the server's net wall-clock cost approaches zero. A GitHub Actions service container was rejected on shape, not capability: its health command is the same sqlcmd loop in different clothing, and the job would serialize the readiness wait before the first step instead of overlapping it. `release.yml` mirrors the wiring in full, so the release gate proves the same suite as CI. The image floats on `2022-latest` as a single version — no 2017/2019 matrix, and no pinning to the production server's version, declined deliberately since the type and write contracts (ADR-0062–0065) are what carry production fidelity; if a cumulative update ever breaks CI, that CU gets pinned and the breakage reported upstream.

The proof surfaces bend around the gate rather than shrink. The SQL Server runnable example ships under `examples/` with its executing test behind the same ignore gate, so the "every example is executed against its README's claims" invariant holds wherever a server exists — in CI, always — and the example's README states the server prerequisite plus the one-liner, relaxing the examples' zero-prerequisite framing for server-backed destinations only. The verify skill gains a SQL Server posture that reads the destination back through `docker exec … sqlcmd`, keeping independent read-back free of new host dependencies. A minimal `CONTRIBUTING.md` becomes the contributor-facing home for build, test, and server-backed test instructions. Alternatives rejected: skip-if-unset at runtime (silent green); an unconditionally required suite (breaks `cargo test` on serverless machines); testcontainers-style in-test container management (a dev-dependency plus a hidden Docker requirement inside the test process); a separate CI job (duplicate build or cache plumbing, plus a merge-gate edit, to buy nineteen seconds of parallelism); and a CU-pinned image (determinism bought at guaranteed staleness).
