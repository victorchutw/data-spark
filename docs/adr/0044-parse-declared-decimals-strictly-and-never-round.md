# Parse Declared Decimals Strictly and Never Round

Data Spark declares exact numerics as `decimal(p,s)` with both parameters mandatory, `1 <= p <= 38` and `0 <= s <= p`, materialized as Arrow `Decimal128(p,s)` and stored as DuckDB `DECIMAL(p,s)` and Parquet `DECIMAL(p,s)`. Accepted text — a CSV cell or a JSON string — is an optional sign followed by plain base-10 digits with at most one decimal point carrying at least one digit on each side (`1.` and `.5` reject): no exponent notation, no thousands separators, no whitespace. A zero-padded integer part such as `007.50` parses, because ADR-0032 guards inference, not declared-type parsing. Fewer fractional digits than the scale rescale losslessly (`1.2` into `decimal(10,2)` stores `1.20`); more fractional digits reject per record, because rounding never happens in a load; and a magnitude of `p` or more digits after scaling rejects as overflow. In JSONL, strings and integers fit — an integer's exact digits were never lost, so it rescales under the same precision bound — while JSON floats reject per record, because their exact digits were already lost to IEEE parsing before the load saw them, and booleans, arrays, and objects reject as shape misfits. Only the canonical `decimal(p,s)` spelling is accepted in declarations — no spaces, signs, or leading zeros in the parameters — so reports and pinned schema files print every declared type byte-identical to its declaration; a malformed declaration (missing parameters, `p` outside `1..=38`, `s > p`) fails the load before any data is read, never per record. Alternatives rejected: rounding over-scale values (silent value corruption in a BI-ready dataset, and the rounding mode itself becomes a hidden contract); accepting JSON floats via serde_json's `arbitrary_precision` (changes number behavior globally for every load; deferred to its own issue if ever wanted); falling back to `float64` beyond some size (reintroduces exactly the precision loss the type exists to prevent); defaulting missing parameters (a default that disagrees with the data truncates silently, and BI datasets need the declared shape to be visible in the definition).
