# Classify SQL Server Transience as Connection-Loss-or-Deadlock on Re-Attemptable Units

The SQL Server destination is the first connector to classify any failure `Transient` (ADR-0048), so the retry engine stops being provably idle. Classification is the product of two independent judgments: whether the failure belongs to the **connection-loss-or-deadlock family**, and whether the failed retry unit can be re-attempted at all under the load mode's write strategy (ADR-0064). The family holds exactly three shapes of the spike-measured error surface (#115): `Io`-kind errors of the connection kinds (`ConnectionRefused`, `ConnectionReset`, `ConnectionAborted`, `BrokenPipe`, `TimedOut`, `UnexpectedEof`), server errors of class ≥ 20 — SQL Server's connection-fatal severities, the shape a mid-bulk session kill surfaces as (error 596, class 21, at `finalize()`) — and deadlock victim 1205, where the server rolls back the batch whole and the connection survives. Everything outside the family keeps ADR-0048's terminal default: authentication 18456, certificate rejection (`InvalidData`), duplicate key 2627, bulk type mismatches, `incompatible_destination_table` (ADR-0065) — deterministic failures where a retry burns backoff to reproduce the same answer.

The family then meets re-attemptability per unit. `begin(mode)` is re-attemptable in every mode: each call opens a fresh connection, and everything begin does — connect, TLS, authentication, Accept Family validation (ADR-0065), full refresh's `BEGIN TRAN` + `DELETE`, merge's stage creation (ADR-0064) — commits nothing, so begin applies the family rule directly; a full-refresh `DELETE` deadlocked by concurrent production workload is a genuinely transient begin failure. `write_chunk` under full refresh and merge is **terminal always, without consulting the family**: chunks run inside the load's single explicit transaction, and any mid-transaction failure — a deadlock rolls back the entire transaction, shedding every already-written chunk — leaves no session that can accept a re-attempt of one chunk, the same structural argument that made DuckDB's in-transaction failures terminal (ADR-0048). `write_chunk` under append applies the family rule, resting on the spike's proof that a failed bulk batch commits nothing: a 1205 re-attempts the same chunk on the surviving connection, and connection-loss failures are transient because the append writer **self-heals** — it marks the client dead, and the next re-attempt reconnects (a pure connect; session-begin validation belongs to the load's begin and is not re-run) before re-sending the same chunk. A failed reconnect classifies under the same family and consumes the same unit's attempt budget (ADR-0049), so reconnection is bounded without new configuration. The classification and the self-heal are one decision and land together: a transient marking without the reconnect would re-invoke a client that cannot succeed. `commit` is never engine-retried (ADR-0048, structural), so the terminal `COMMIT` of full refresh and merge surfaces its failures unchanged.

Two standing choices ride along. The connector leaves `LOCK_TIMEOUT` at the server default of infinite wait — a batch tool blocking on a lock is correct behavior, and the operator can kill the load — so lock-timeout error 1222 is unreachable and deliberately unclassified. And SQL Server does not trigger ADR-0049's jitter revisit condition: jitter decorrelates many concurrent clients against a shared throttled service, and this connector runs one in-flight write (ADR-0068) in one process. The retry defaults (3 attempts, 200 ms initial, 5000 ms cap) also stay untouched — they are load-level configuration, not connector surface; outages longer than the default budget, a server restart among them, are tuning guidance for the destination guide, not a defaults change.

Alternatives rejected: a per-error-code allowlist with no class ≥ 20 family (every unforeseen connection-fatal error would land terminal and demand a code-by-code chase; the severity class is the server's own declaration that the connection is dead, and a dead connection's failed batch is provably uncommitted); classifying known-transient server codes at begin, such as Azure's 4060/40613 database-unavailable family (the production environment this cycle serves is on-premises, where 4060 is a configuration error rather than a failover transient — the door reopens if an Azure destination materializes); marking append connection-loss terminal and deferring the self-heal (the longest production loads are appends, and a mid-load connection drop is the single most valuable retry case — without the reconnect this connector's classification would stay nearly hollow); re-running Accept Family validation on reconnect (mid-load DDL against the target is not a failure mode retry should paper over, and the validation belongs to session begin).
