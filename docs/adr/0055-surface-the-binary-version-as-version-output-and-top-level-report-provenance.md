# Surface the Binary Version as --version Output and Top-Level Report Provenance

The binary's version — `CARGO_PKG_VERSION`, the one version `Cargo.toml` declares — is surfaced in two places. On the CLI, clap's `#[command(version)]` gives `data-spark --version` and `-V`, which print `data-spark <version>` and exit `0`, so a downloaded binary can identify itself — the README's post-download check — and the release workflow can assert that the **shipped artifact** reports the tag's version, a stronger smoke test than validating the source tree it was built from. In the load report, every report gains an additive top-level **`binary_version`** string, on the success and the failure path alike, so an archived report names the build that wrote it. `report_version` stays `1` — the settled additive precedent (ADR-0030, ADR-0042, ADR-0046, ADR-0047, ADR-0050, ADR-0053: additive fields do not change how existing readers parse the report). Because both surfaces read `CARGO_PKG_VERSION` at compile time, no new hand-maintained version location exists; the release checklist's version locations are unchanged.

Placement follows ADR-0050's own test, which kept `retry` inside `execution` because retry is an execution-behavior fact that lives where `chunk_rows` and `batch_count` already do. A binary version is not execution behavior — it is provenance for the whole report, the same register as `report_version` and `load_id` — so it lives top-level beside them. The two versions state different things and move independently: `report_version` is the contract for reading the document, `binary_version` the build that wrote it. One cost is accepted: report content now differs across releases, so a byte-identity A/B comparison between binaries of different versions shows this field as the intended difference rather than proving equivalence.

Alternatives rejected: placing the field inside `execution` (provenance is not execution behavior; it fails the ADR-0050 placement test); a hand-declared version constant beside `CARGO_PKG_VERSION` (a second declaration can drift from `Cargo.toml`; the compile-time value cannot); bumping `report_version` (additive fields do not change how existing readers parse the report); leaving the binary unversioned and attributing archived reports out of band (the report is the machine-readable record of a load, and a version-free single-name release asset installed as `data-spark` leaves nothing else to recover the version from).
