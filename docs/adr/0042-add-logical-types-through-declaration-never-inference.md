# Add Logical Types Through Declaration, Never Inference

Data Spark adds `timestamp`, `timestamptz`, and `decimal(p,s)` to the dataset field-type vocabulary as declared-only types: they enter a schema exclusively through explicit declaration — `schema.overrides` in the load definition, and the pinned schema files a declared load bootstraps or extends — never through inference. The observation lattice and its guards (ADR-0006, ADR-0031, ADR-0032) are untouched, so a load declaring none of the new types behaves exactly as before, and value-level fit for a declared type is parse-based on the value itself rather than lattice-based, because no observation widens to a declared type in either direction. Pin comparison treats declared types as exactly equal or different: `decimal(10,2)` versus `decimal(12,2)` is a contradiction under every drift policy — surfacing as a schema override conflict when an override contradicts the pin, per ADR-0038's conflict-before-drift ordering — and never widenable drift, while a newly added nullable declared-type field remains legal additive drift that rewrites the pin (ADR-0034). The load definition stays the declaration of record: a pinned declared-type field requires its re-declaring override in every load, and omitting the override fails the load as schema drift naming the pinned and effective types with a missing-override hint, because without the declaration inference could never reproduce the pinned dataset — and a definition-level omission must fail once, not flood the load with per-record rejections. The new names are additive vocabulary inside existing contracts: load definitions and pinned schemas stay `version: 1`, `report_version` is unchanged, and reports and pin files print a declared type byte-identical to its declaration. Alternatives rejected: inferring timestamps or decimals from observed data (data-dependent column types defeat the stability that ADR-0031/0032 protect, and any inference menu reintroduces locale and format guessing), widening rules between declared types such as decimal precision growth (implies destination-side `ALTER`s and silently changing contracts), letting the pin alone carry a declared type without the override (two declarations of record that can drift apart silently), and bumping contract versions for the additive vocabulary (the addition parses identically for every existing definition, so a bump would only gate old files for no benefit).
