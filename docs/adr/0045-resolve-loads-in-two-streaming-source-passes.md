# Resolve Loads in Two Streaming Source Passes

Data Spark's `local_file` source moves from whole-input, single-batch materialization to two sequential streaming passes over the source. Pass 1 streams the entire input once holding only bounded state — the CSV header or JSONL key union, the per-column observed-type lattices (whole-input and surviving-records), per-record check outcomes, rejection counts, and the streaming outputs below — and completes every whole-input decision at end of input exactly as the single-batch path did: inference, transform resolution, overrides, pin comparison, drift verdicts, and additive-drift added-field types (from surviving records) are all judged against the whole input, and the reject threshold is evaluated once, at end of pass 1, over full-input counts — never early-aborted — so a breach anywhere in the source fails the load with the established code and message wording and zero side effects (no pin persisted, destination untouched). Pinned-schema bootstrap and additive rewrites persist where they always did: after the threshold gate, before the first destination write. Pass 2 re-reads the source and materializes `RecordBatch` chunks of at most `execution.chunk_rows` surviving records against the now-fixed plan, re-running the same per-record checks only to skip the records pass 1 rejected; check outcomes are a pure function of (record, resolved plan), so the passes agree, and chunk boundaries are deterministic — the same source bytes and the same bound always produce the same split, the retry and parallelism unit future work builds on. The accepted trade-off is the second sequential read of the source, paid to preserve whole-input semantics and the pre-write threshold gate verbatim.

Rejected records stream to the `rejected-records.jsonl` artifact during pass 1 instead of accumulating in memory, preserving artifact content and line ordering byte-for-byte. Where a rejection cannot be confirmed until the end-of-input shape verdict — JSONL validation rejections, since the dataset shape and therefore verdicts like missing-field drift are decidable only at end of input — the record buffers through a line-ordered spill file and merges into the artifact after a passing verdict, or is discarded with a failing one, keeping the invariant that a shape-drift failure's artifact carries only parse rejections; the spill is never unbounded memory. Because the JSONL check set derivable from the directive alone (pinned fields plus overrides outside the pin) equals the resolved check set whenever the verdict passes, pass 1 judges records order-free ("violates any check") and the merge renders each spilled record's rejection against the resolved checks.

Between the passes the source can change, so the load carries a dual mutation guard with one new failure code, `source_changed_during_load`. Semantically, pass 2 fails on a per-record check outcome that differs from pass 1, an end-of-input record-count mismatch, or a JSONL key outside the resolved shape. Byte-wise, each pass folds every byte it reads through an FNV-1a hash incidentally to its existing read — no third read happens — and the comparison lands on the pull after the final chunk, which places it before the terminal commit for full refresh (destination untouched) and at end of stream for append (the committed chunk prefix stays visible and is reported honestly, per ADR-0047). The hash is a same-process guard against concurrent modification, not a cryptographic integrity check.

Alternatives rejected: sampling-based inference with one pass (a sample can misjudge the type lattice and the reject threshold, changing schema decisions the whole-input contract fixed); spilling parsed records to disk between passes (trades the second read for disk volume proportional to the source plus serialization cost, and the source file already is that spill); early-aborting pass 1 on a threshold breach (changes the failure message's full-input counts and the artifact's completeness — deferred as a future opt-in optimization); file locking instead of divergence detection (advisory locks are not enforceable across arbitrary writers, while detection fails honestly wherever the change surfaces).
