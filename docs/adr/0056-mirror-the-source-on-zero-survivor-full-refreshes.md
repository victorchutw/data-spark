# Mirror the Source on Zero-Survivor Full Refreshes

A `full_refresh` load that completes with zero surviving records replaces the destination dataset with an empty one and exits `0`, and Data Spark adds no guard against that outcome — no contract key, no failure code, no behavior change. The grounding is the mode's own definition: a full refresh replaces the destination dataset with the source's current records (CONTEXT.md), and under that mirror semantics the two routes into an empty dataset are different events. An empty delivery mirrored as an empty dataset is the mode working as defined — the source's current records are zero, and nothing unfaithful happened. No knob guards that route today (a header-only CSV empties the dataset at the default `reject_threshold: 0` — `header_only_csv_completes_as_an_empty_load`, tests/cli_load_contract.rs), and none should. A fully-rejected delivery is the unfaithful route — the source had records and none could be loaded — and that route is exactly what `reject_threshold` guards at its default `0` (ADR-0020): the load fails with `reject_threshold_exceeded` before the pinned schema is persisted and before the destination is touched (ADR-0045). Raising the threshold is explicit consent to partial loss, up to and including a whole delivery.

The asymmetry — the threshold guards the rejection route but not the empty-delivery route — is deliberate, not a gap: an empty delivery rejects nothing, so there is no count for the gate to judge. Nor can the load itself tell a legitimately empty source from a delivery that went missing upstream; a guard inside the load would have to turn the faithful case into a failure to catch the abnormal one. The posture is documented instead: the threshold's promise is scoped honestly — keeping it at `0` keeps a dataset from being emptied *by rejection* — and a pipeline for which an empty delivery is abnormal guards the delivery upstream, before the load is invoked. The rejection route is format-agnostic: it needs only a source that still offers a shape with no survivor to observe, which a CSV header provides whatever the records do, and which JSONL records that parse but reject provide through their own field names — only an all-unparseable JSONL file fails instead (`malformed_jsonl`), having offered no shape at all. Were this decision ever revisited, the natural guard slot is the threshold gate, where the load mode, the full-input counts, and the schema decision are all in hand before anything is written.

Alternatives rejected: a minimum-surviving-records floor as a sibling key to `reject_threshold` (data-quality SLO machinery rather than a destruction guard, and a contract key whose number no user can pick well); refusing an empty full refresh unless explicitly opted in (breaks the mode's mirror meaning, turns the legitimate empty-source case into a failure by default, and changes the outcome of definitions that succeed today); deriving a guard from the threshold by treating every-record-rejected as a breach regardless of the configured number (overloads `reject_threshold` with a second meaning and still misses the empty-delivery route entirely).
