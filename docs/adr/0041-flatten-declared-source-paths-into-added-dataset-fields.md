# Flatten Declared Source Paths Into Added Dataset Fields

Data Spark will flatten nested JSON through an optional `flatten` key in the `transform:` block — a map of dot-notation source path to author-written dataset field name — rather than through a global flatten-everything mode, so the dataset column set stays config-determined instead of data-dependent. The fixed transform order extends to flatten → select → rename: flatten evaluates first, against the observed source shape, adding one dataset field per declared path in declaration order after the observed fields, and its outputs are ordinary fields to selection and renaming. Flattening is purely additive — the parent source field keeps materializing as JSON text, and field selection remains the only mechanism that removes fields. Extraction is total: a scalar leaf yields the value into the inference lattice; a null anywhere on the path, a missing leaf key, or an intermediate segment that is not an object yields null; an object or array leaf yields its compact JSON text, so everything below an extracted path stays JSON text unless declared as its own deeper path. Extraction never rejects a record — strictness stays delegated to pinned schemas and overrides, which already reject per-record misfits — because the additive parent preserves the original value, and a reject boundary between an absent, a null, and a misshapen parent could not be explained. Paths are dot-notation with at least two non-empty segments, address object keys only (no array indexing), and take their depth from the declaration, so no depth limit exists; a source key containing a literal dot is unaddressable. A flatten output's dataset name must be unique among config-determined names before any I/O, must appear in a declared select list (no no-op extraction, matching the rename rule), and may never shadow an observed source field — even one selection would drop — failing at read time otherwise. Flattening requires a JSONL source; declaring it for CSV is a definition error. Alternatives rejected: global auto-flatten (data-dependent column sets defeat stable analytical columns and drift control), consuming the parent field (silent data loss or a remainder grammar), rejecting shape mismatches at extraction (a second rejection source duplicating the pin's job), and JSON Pointer syntax (escape grammar alien to the BI audience dot notation serves).
