# Configure Parallelism as One Scalar Clamped to the Connector Limit

The parallelism window (ADR-0051) is load-definition configuration in the `execution` block ADR-0046 designated for it: one new optional scalar key, `execution.parallelism`, a nonzero unsigned integer beside `chunk_rows` and `retry`. Absent — the block or the key — the effective parallelism is the connector's declared limit for the load's mode, ADR-0023's conservative connector-specific default: 1 everywhere in the shipped matrix, and a future concurrent-capable connector's safe declared ceiling without anyone editing definitions. Present, the effective parallelism is **`min(configured, limit(mode))`** — the Connector Parallelism Limit is a hard cap the configuration can never exceed, never an error to exceed, so one definition stays valid across destinations with different limits. `parallelism: 1` is the explicit serial form.

The key deserializes as a nonzero unsigned integer (the `chunk_rows` and `max_attempts` precedent), so `parallelism: 0`, negative, and non-integer values fail YAML parsing under the existing `invalid_load_definition_yaml` code; unknown keys beside it are rejected recursively (ADR-0037), and a top-level `parallelism` key remains unknown. The feature introduces **zero new failure codes**. Configuration is load-definition YAML only — no CLI flag, no connector-settings surface: how parallel a load runs is a property of the load, repeatable across invocations, not of one invocation's command line.

Alternatives rejected: failing when the configured value exceeds the limit (turns a portable definition into a per-destination one and makes the safe clamp an error state; the report states the clamp instead, ADR-0053); per-dimension knobs — read, transform, write parallelism (only destination writes run concurrently in this design, and a knob without a consumer is contract surface waiting to contradict a future decision); a cross-field cap on parallelism × `chunk_rows` (two honest knobs with a documented product beat a synthetic third limit that would guess at the machine's memory); a CLI override flag (the one-off override precedent is reserved for artifact routing, ADR-0015 — execution behavior stays in the versioned definition); a boolean `parallel: true` with an engine-chosen width (hides the number that decides peak memory, the one fact the user must own).
